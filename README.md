# 每日阅读 · 考研英语

把今天背的单词变成一篇**考研英语阅读真题风格**的文章：多层嵌套的长句、让步—反驳的论证结构、
长难句拆解、按考研五大题型出的理解题。**全程本地运行，数据不出自己电脑。**

> 界面截图：[docs/screenshot-exam.png](docs/screenshot-exam.png)（真题模式的实际输出）

## 先看这张表：你能不能用

| | 要求 |
| --- | --- |
| **操作系统** | **Windows 10 / 11**。截图识别调用的是 Windows 系统自带的 OCR，**macOS 和 Linux 用不了** |
| **运行时** | [Node.js 18 或更高](https://nodejs.org)。装一次就行 |
| **模型** | 一个 DeepSeek API Key（[在这里申请](https://platform.deepseek.com/api_keys)）。一篇文章大约几分钱 |
| **第三方依赖** | **零**。不需要 `npm install`，没有 `package.json`，没有任何库 |

> 不想花钱也可以只用手动粘贴 + 不生成文章？不行——**没有 API Key 就没法生成文章**，这是唯一必须花钱的地方。
> 截图识别本身是免费的（本地 OCR，不消耗任何额度）。

## 30 秒上手

```
1. git clone https://github.com/YuanCUMT/daily-reading.git
   （或者点 Code → Download ZIP 解压）

2. 双击目录里的 start.cmd
   → 会自动弹出浏览器打开 http://127.0.0.1:8787

3. 右上角 ⚙️ 设置 → 填 DeepSeek API Key → 保存

4. 点「导入单词」→ 把百词斩截图拖进去（或 Ctrl+V 粘贴）
   → 点「开始识别」→ 勾选要用的词 → 保存

5. 点「生成文章」，等半分钟
```

**关掉那个黑窗口就是停止服务。**

想做桌面快捷方式（可选）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/install-shortcut.ps1
```

它会用项目里的 `icon.ico` 在桌面建一个「每日阅读·考研英语」图标，之后直接点图标就行。

## 每天怎么用

| 步骤 | 操作 | 花多久 |
| --- | --- | --- |
| 1 | 百词斩背完今天的单词，截几张图 | — |
| 2 | 把截图**一次全拖进**阅读器（最多 12 张） | 几秒 |
| 3 | 点「开始识别」，勾掉不想要的词 | 几秒 |
| 4 | 点「生成文章」 | 等 30 秒 |
| 5 | 读 | — |

- **可以一张一张加**：分几次导入会累加去重，不会互相覆盖。第二批全是重复词时会提示「新增 0 个，跳过重复 N 个」。
- **清空**：侧栏「今日单词」右上角（只清单词，已生成的文章不受影响）。
- **回看**：每篇文章存成 `data/articles/日期.json`，左侧「历史文章」随时翻。

## 阅读时查词 + 我的生词

读文章时总有些词不是今天的作业词但也不认识。**点正文里任意单词**就弹出浮层，不用复制去别处搜。

- 今天的词表里的词，直接拿词汇卡上的释义，**不花额度**
- 别的词才会调一次模型查；查过的存进 `data/dict/`，再点就命中缓存，**同一个词只花一次钱**
- 浮层里有音标、词性、中文释义、例句，还能点 🔊 朗读、跳剑桥词典
- 点「☆ 收藏」收进侧栏的**我的生词**

正文里的高亮分两种：**黄色**是今天要背的目标词，**淡蓝底 + 虚线下划线**是你自己收进生词本的词。收藏之后正文里会**立刻**变色，不用等重新生成文章。
生词本存在 `data/marks.json`，可以单独移出，也可以一键清空；查词缓存可以在设置里清（换了模型、觉得释义不对时用）。

## 两种文章模式

顶栏日期右边有个下拉框，一键切换；也可以在设置里改。

### 复习模式（默认）

目标是把今天背的词记住：当天的词**尽量全部用上**，句子偏短、能靠语境猜词。

### 真题模式

目标是**像考研英语 Part A 的原文**，不追求词汇覆盖率。

| | 复习模式 | 真题模式 |
| --- | --- | --- |
| 目标词 | 当天全部 | 从词表里挑 12–15 个（可调） |
| 句法 | 短句、好读 | 平均句长 25–30 词，每段至少一个两层以上从句的长句 |
| 结构 | 话题自然展开 | 必须有**让步—反驳**，禁止「现象→科学→历史→对策→升华」模板 |
| 开头 | 随意 | 直接切入现象/数据/观点，禁止故事化虚构开头 |
| 地点 | 真实具体 | 真实具体（禁止「某个大陆城市」这类含糊表述） |
| 语域 | 宽松 | 严格书面语，禁口语化动词（如 trash 当「毁掉」、smuggle 当「偷偷加入」） |
| 题型 | 覆盖不同类别 | 细节题 2–3、推断题 1–2，词义/态度/主旨各不超过 1 |
| 选项 | 常规 | 正确项**必须是同义改写**（不许照抄原文），干扰项按**偷换概念 / 以偏概全 / 过度推断 / 张冠李戴 / 正话反说**设计，并在解析里逐个点名 |

两种模式都会检查每个词是否真的出现在文中。复习模式下没用到的词会在标题下方标出来；
真题模式只用一部分词是正常的，所以不报警，改为显示「本篇用到 12/44 个词」。

设置里还能调：难度（考研英语一 / 英语二 / 外刊原文）、段落数、题量、题材、长难句开关、题目开关。

## 截图识别是怎么做的

用 **Windows 系统自带的 OCR**（`Windows.Media.Ocr`）——本地运行，不联网，不需要额外 Key，也不算你 DeepSeek 的额度。

关键在于**按字号挑词**，而且**每张图各算各的阈值**：

- 百词斩单词卡上，目标单词是屏幕上最大的那行字，例句和界面文字都更小
- OCR 结果里每个词都带包围盒尺寸，所以只保留最大字号的词，例句和「认识 / 不认识」这类界面文字自动滤掉
- 整张图字号都差不多时（比如单词本的列表页），退回「全部保留」
- 阈值必须逐图算：单词卡的大字和列表页的小字混在同一批里时，统一阈值会让大字把小字全压掉

实测：一张单词卡只挑出那一个目标词；一张 6 个词的列表截图能全认出来；两种混着一次传，7 个词全在。

坏图不会拖垮整批：能认的照常认，认不出的单独列出来；整批都失败会直接告诉你原因。

识别完还会用 AI 校正一遍拼写、剔除界面噪声（可关掉）：

```
OCR 认成：cautlous  →  自动修正为：cautious
OCR 认成：ViVid     →  自动修正为：vivid
```

候选词列出来后**拼写可以直接在输入框里改**。不想用截图就切到「手动粘贴」标签，一行一个词。

## 常见问题

**双击 `start.cmd` 弹出一屏中文提示说「没有找到 Node.js」**：就是字面意思，先装 Node.js。
去 [nodejs.org](https://nodejs.org) 下载 LTS 版本，一路「下一步」，装完关掉窗口重新双击。
如果装完还提示，重启一次电脑——新装的程序要让系统重新读取环境变量才认得到。

**提示「Node.js 版本太旧」**：装的版本低于 18。去官网装最新 LTS 覆盖掉就行（程序用到了 18 才有的 `fetch`）。

**启动时提示端口被占用**：说明已经开着一个了，程序会把浏览器指向已有实例。
**改过代码之后一定要先关掉旧窗口再重启** —— Node 会把模块缓存在进程里，不然改动不生效。

**截图识别说没有 OCR 语言包**：Windows 设置 → 时间和语言 → 语言和区域 → 添加中文（简体）或英语（美国）语言包。

**截图识别不出词**：确认截图里单词清晰、没被裁掉。单词卡截图效果最好，整屏单词列表也能认。
识别结果下方有一份「原始识别文字」，可以对照看看 OCR 到底读到了什么。

**OCR 认错了词**：候选词可以逐个手改；也可以把「用 AI 校正拼写」勾上（默认开）。

**生成时报 401 / 402**：API Key 不对或余额不足，去设置里重填。

**生成很慢**：一次要写 6 段英文 + 翻译 + 长难句 + 题目，通常 30~60 秒，属正常。

**想换别的模型**：设置里的「接口地址 + 模型」支持任何 OpenAI 兼容服务
（`https://api.openai.com/v1`、本地 Ollama、One-API 中转都可以）。

**换端口**：`set PORT=9000 && node server.js`。

## 开发笔记：几个踩过的坑

改代码前值得看一眼，能省不少时间。

**`start.cmd` 必须纯 ASCII + CRLF。** `cmd.exe` 是按 ANSI 代码页逐字节解析 `.cmd` 的，不是 UTF-8。
文件里写中文再配 `chcp 65001`，会让 cmd 的文件位置指针错位，后面的行直接乱掉——
曾经把 `echo` 吃成 `ho`、`node server.js` 吃成 `erver.js`，双击图标只闪一下报错就退出。
只有 LF 换行则会让 `if (...)` 这类块级语法解析失败。

因此这个文件有两条约束同时成立：
1. **不用 `if (...)` 块，改用 `goto` 标签。** 块语法只要遇到一行裸 LF 就炸；标签不受影响。
2. **中文提示单独放 `tools/msg-*.txt`（UTF-8 无 BOM），由 `type` 打出来。**
   `.cmd` 自己仍然一个中文都不能有，但用户在 `chcp 65001` 下看到的是中文。
   注意不能带 BOM，否则 `type` 会把 `EF BB BF` 打成乱码。

测试里有断言守着这些（ASCII、CRLF、两个提示文件的编码）。

**`lib/ocr.ps1` 也必须纯 ASCII**，同理：PowerShell 5.1 按 ANSI 读 `.ps1`。

**`tools/install-shortcut.ps1` 反过来，必须带 UTF-8 BOM**，因为它里面有中文快捷方式名。

**不要再在 catch 里调 `[System.IO.Path]::GetFileName`**：它对含非法字符的路径会抛异常，
把真正的错误盖掉（这个坑让我们排查了半天「路径中具有非法字符」）。

**OCR 桥有版本号握手**：`ocr.js` 和 `ocr.ps1` 之间传 `bridge` 版本，对不上会明确提示「请重启服务」，
而不是抛出莫名其妙的错误。原因见下条。

**Node 的模块缓存**：改完代码必须重启服务。服务进程里缓存的 `ocr.js` 和磁盘上的 `ocr.ps1`
版本不一致时，OCR 会失败——这就是当初「多图识别报错」的真正原因。

**`.gitattributes` 强制 `.cmd` 用 CRLF**，避免不同机器的 `core.autocrlf` 把行尾改掉。
